Going live — notes

  • HTTPS / mixed content: your page must be served over HTTPS and the Status API must be reachable over HTTPS too — browsers block EventSource and fetch to plain HTTP from an HTTPS page.
  • CORS: the Status API sends Access-Control-Allow-Origin per FEN_CORS_ORIGINS (default *); narrow it to your portal origin when going live.
  • Read-only (ADR-001): the widget never writes anything — it only reads GET /api/v1/status/{id} and subscribes to GET /api/v1/events/{id} (SSE, contract in web/api.md §4b).
  • Live updates: while the stream is down the widget falls back to 15s polling; embedders whose CSP blocks EventSource can set live="off".
  • challengeWindowEnd: the countdown is deliberately NOT rendered — gated on ADR-006 acceptance (see web/widget/README.md).
  • Local demo: to see live statuses here, run the stack (docker compose up --build status-api) and seed a couple of records; otherwise the badges show the “Status API unavailable” state.
